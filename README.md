### 2. Архитектура системы

Приложение спроектировано по микросервисной архитектуре и состоит из **4 независимых изолированных контейнеров**, объединенных в единую мостовую сеть `game-network` (bridge):

```
                        ┌───────────────────────────────────────────────┐
                        │             Хост-система (Браузер)            │
                        └───────────────────────┬───────────────────────┘
                                                │ http://localhost:8080
                                                ▼
     ┌──────────────────────────────────────────────────────────────────────────────────┐
     │  ВИРТУАЛЬНАЯ СЕТЬ DOCKER: game-network (driver: bridge)                          │
     │                                                                                  │
     │   ┌────────────────────────┐         http://backend:5000/api                     │
     │   │   game-frontend        ├────────────────────────────────┐                    │
     │   │   (Nginx Alpine :80)   │                                │                    │
     │   └────────────────────────┘                                ▼                    │
     │                                                   ┌────────────────────┐         │
     │                                                   │   game-backend     │         │
     │                                                   │ (Node.js Express)  │         │
     │                                                   └────┬───────────┬───┘         │
     │                            postgres://db:5432/gamedb   │           │             │
     │                   ┌────────────────────────────────────┘           │             │
     │                   ▼                                                ▼             │
     │   ┌───────────────────────────────┐               ┌──────────────────────────┐   │
     │   │   game-database               │               │   game-web-service       │   │
     │   │   (PostgreSQL 16 Alpine)      │               │   (Каталог видеоигр)     │   │
     │   │   healthcheck + init.sql      │               │   (Node.js Express :5001)│   │
     │   └───────────────┬───────────────┘               └──────────────────────────┘   │
     │                   │                                                              │
     └───────────────────┼──────────────────────────────────────────────────────────────┘
                         ▼
             ┌───────────────────────┐
             │  Volume: postgres_data│
             │  (Персистентность БД) │
             └───────────────────────┘
```

#### Роли компонентов:
1. **Frontend (`game-frontend` | Nginx Alpine, порт `8080:80`):**
   - Пользовательский веб-интерфейс в стиле игрового дашборда с адаптивным темным оформлением.
   - **Кнопка 1:** Отправляет запрос к бэкенду на получение данных из внутренней реляционной базы данных (PostgreSQL).
   - **Кнопка 2:** Отправляет запрос к бэкенду на получение данных от микросервиса каталога с фильтрацией по жанрам и объему оперативной памяти (RAM).
   - Дополнительно: возможность в 1 клик добавить игру из каталога в личную библиотеку, изменить статус (В процессе / Пройдено / В планах), начислить часы прохождения, а также просмотреть live-диагностику healthcheck всех контейнеров.
2. **Backend (`game-backend` | Node.js 20 Express, порт `5000:5000`):**
   - Единый REST API шлюз приложения.
   - Реализует CRUD-операции с PostgreSQL через пул соединений с пулом повторных попыток.
   - Взаимодействует со специализированным Web-сервисом (каталог видеоигр).
   - Предоставляет эндпоинт `/health`, проверяющий статус базы данных и Web-сервиса.
3. **Database (`game-database` | PostgreSQL 16 Alpine, порт `5432:5432`):**
   - Хранит записи пользовательской библиотеки (таблица `user_library`).
   - Автоматически инициализируется при первом запуске через скрипт `db/init.sql`.
   - Имеет встроенный `healthcheck` (`pg_isready -U postgres -d gamedb`), благодаря которому бэкенд стартует только после полной готовности базы данных.
   - Данные сохраняются между перезапусками в постоянный том `postgres_data`.
4. **Web-service (`game-web-service` | Node.js Express, порт `5001:5001`):**
   - Специализированный микросервис варианта 37.
   - Содержит базу видеоигр с подробными системными требованиями: ОС, процессор, минимальный объем RAM, видеокарта, место на жестком диске.
   - Поддерживает фильтрацию по жанрам, системным характеристикам (RAM) и текстовый поиск.

### 3. Быстрый запуск проекта

#### 1. Клонирование и запуск в одну команду:
```bash
docker compose up --build -d
```

#### 2. Проверка состояния всех 4 контейнеров:
```bash
docker compose ps
```
*Все 4 контейнера должны иметь статус `Up` (для базы данных — `Up (healthy)`).*

#### 3. Открытие веб-интерфейса:
Откройте в браузере: **[http://localhost:8080](http://localhost:8080)**

#### 4. Просмотр логов в реальном времени:
```bash
docker compose logs -f
```

#### 5. Остановка и очистка:
```bash
# Остановка контейнеров:
docker compose down

# Остановка с удалением томов базы данных (полный сброс):
docker compose down -v
```

### 5. Спецификация REST API

#### Эндпоинты бэкенда (`http://localhost:5000` или через фронтенд `/api`):

| Метод | URL | Описание | Источник данных |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | Диагностика всех сервисов (БД + Web-Service) | Backend / Подсистемы |
| `GET` | `/api/library` | **Кнопка 1:** Список игр в библиотеке | **PostgreSQL (user_library)** |
| `POST` | `/api/library` | Добавление новой игры в библиотеку | **PostgreSQL (INSERT)** |
| `PATCH` | `/api/library/:id` | Обновление времени, статуса или оценки | **PostgreSQL (UPDATE)** |
| `DELETE`| `/api/library/:id` | Удаление игры из библиотеки | **PostgreSQL (DELETE)** |
| `GET` | `/api/stats` | Агрегированная статистика (часы, игры, рейтинг) | **PostgreSQL (Агрегация)** |
| `GET` | `/api/catalog/search`| **Кнопка 2:** Поиск в каталоге с фильтрами | **Web-сервис (порт 5001)** |
| `GET` | `/api/catalog/genres`| Список доступных игровых жанров | **Web-сервис (порт 5001)** |

### 6. Сценарии тестирования через консоль (curl)

Вы можете протестировать работоспособность прямо из терминала:

#### Тест 1: Проверка статуса всех компонентов
```bash
curl -s http://localhost:5000/health | jq
```

#### Тест 2: Запрос данных из внутренней БД (Кнопка 1)
```bash
curl -s "http://localhost:5000/api/library?status=completed" | jq
```

#### Тест 3: Запрос данных из Web-сервиса с фильтром по RAM (Кнопка 2)
```bash
curl -s "http://localhost:5000/api/catalog/search?genre=RPG&max_ram_gb=8" | jq
```

#### Тест 4: Добавление новой игры в БД через Backend
```bash
curl -s -X POST http://localhost:5000/api/library \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Half-Life 2",
    "genre": "Shooter / Sci-Fi",
    "status": "completed",
    "user_rating": 10,
    "playtime_hours": 35.5,
    "min_ram_gb": 4,
    "notes": "Легендарный шедевр Valve",
    "cover_emoji": "λ"
  }' | jq
```

#### Тест 5: Получение агрегированной статистики
```bash
curl -s http://localhost:5000/api/stats | jq
```
